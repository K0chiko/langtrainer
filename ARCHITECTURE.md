# Language Trainer: архитектура

Приложение записывает разговоры с носителем языка, находит ошибки, копит их в базе и превращает в карточки и советы.
Сейчас: пользователь учит английский. Позже: собеседница может учить русский на тех же механизмах.

## Принципы

1. **Двунаправленность с первого дня.** Нигде нет «английский» и «русский» в коде. Есть `Learner` (кто учится), `native_lang`, `target_lang`. Разбор реплики зависит от профиля говорящего, а не от константы.
2. **Анализатор заменяем.** Весь разбор ошибок идёт через интерфейс `Analyzer`. Реализации выбираются в `llm.py`: Claude Code CLI по подписке, любой OpenAI-совместимый сервер (локальные модели, платные API) и Anthropic API.
3. **Каждый конвейерный шаг можно запускать отдельно.** Запись → транскрипт → разбор → карточки. Каждый шаг читает и пишет в БД, поэтому любой из них можно перезапустить.
4. **Всё локально, общего сервера нет.** Каждый пользователь запускает своё приложение на своём компьютере. Аудио не уходит в облако, в Claude уходит только текст.
5. **Кроссплатформенность: macOS, Windows, Linux.** Всё, что зависит от ОС (распознавание речи, запись звука), спрятано за интерфейсами с отдельной реализацией на платформу.
6. **Место хранения настраивается.** БД и аудио задаются в конфиге, так что их можно положить на Synology.

## Конвейер

```
Запись (2 дорожки)  →  STT (Whisper, локально)  →  Реплики  →  Analyzer  →  Ошибки  →  Карточки (SRS)  →  Советы
 мик | системный звук     по дорожке отдельно        в БД       (Claude)      в БД         в БД             сводки
```

**Две дорожки вместо диаризации.** Микрофон — это ты, системный звук звонка — собеседница. Распознавание идёт по каждой дорожке отдельно, поэтому не нужно угадывать, кто говорит. Это надёжнее любой диаризации.

**Захват звука на Mac.** Браузер не умеет писать системный звук, поэтому нужен маленький рекордер:
- Фаза 1: загрузка готовых файлов (две дорожки или один стерео-файл) через веб-интерфейс.
- Фаза 2: рекордер по одной реализации на ОС, всё пишет два WAV в папку, а бэкенд подхватывает их сам:
  - macOS: ScreenCaptureKit (13+) или виртуальное устройство BlackHole;
  - Windows: WASAPI loopback (системный звук доступен без доп. программ);
  - Linux: монитор-источник PulseAudio/PipeWire.

**STT (интерфейс `Transcriber`).** По умолчанию везде `faster-whisper` (CPU, быстрее на видеокарте NVIDIA; ffmpeg не нужен). На Mac с Apple Silicon можно включить `mlx-whisper` вручную (`LT_TRANSCRIBER=mlx`): он быстрее, но требует ffmpeg в PATH. Выход: реплики с таймкодами и уверенностью. Низкая уверенность распознавания помечается, чтобы не записать в ошибки то, что на деле ошибка Whisper.

**Analyzer (подписка, без API-ключа).** Бэкенд запускает `claude -p --output-format json` с JSON-схемой ответа. Это официальный CLI под твоей подпиской, отдельной оплаты нет, действуют обычные лимиты подписки. Разговор на 30 минут — это несколько тысяч слов, так что на лимиты это почти не влияет. Реплики отправляются пачками с контекстом соседних реплик, потому что без контекста ошибку не отличить от нормальной разговорной речи.

## Модель данных (SQLite)

| Таблица | Назначение |
|---|---|
| `learner` | id, имя, native_lang, target_lang, уровень CEFR |
| `session` | один разговор: дата, участники, пути к аудио |
| `participant` | кто в сессии: learner или нативный собеседник, на какой дорожке |
| `utterance` | реплика: session, participant, текст, start/end, asr_confidence |
| `error` | utterance, learner, категория, `original`, `corrected`, объяснение, серьёзность, `rule_id` |
| `rule` | справочник правил/тем (артикли, Present Perfect, предлоги…) на пару языков |
| `card` | карточка: error или rule, тип (исправь фразу, заполни пропуск, перевод), front/back |
| `review` | повтор карточки: когда, оценка, интервал (SRS, начнём с FSRS или SM-2) |
| `insight` | сводка: «топ-3 слабых места за неделю», совет, период |

Категории ошибок: грамматика, лексика/выбор слова, предлоги, артикли, порядок слов, время глагола, неестественная фраза, произношение (позже, по ASR-сигналам).
Слабые места = `error` сгруппированные по `rule_id`. Именно они дают карточки, советы и статистику прогресса.

**Зеркальный режим.** Реплики собеседницы-нативной анализируются «в обратную сторону»: её русские реплики, если она учит русский, идут тем же `Analyzer` с профилем `native=en, target=ru`. Менять схему не нужно, достаточно второго `learner`.

## Где хранятся данные (в том числе Synology)

Адрес БД и папка с аудио задаются в конфиге. Слой данных пишем на SQLModel без привязки к SQLite-специфике, поэтому есть три варианта:

1. **SQLite локально** (по умолчанию) плюс регулярная копия на Synology. Проще всего.
2. **PostgreSQL на Synology** в Docker. Приложение на компьютере ходит в неё по сети. Удобно, если базой пользуются несколько устройств или людей.
3. **SQLite-файл прямо на шаре Synology (SMB/NFS): не рекомендую.** Блокировки файлов по сети ненадёжны, база может повредиться.

Аудио можно держать на Synology отдельно, это обычные файлы. Для двух людей каждый использует свою БД или общую Postgres с `learner_id` в таблицах.

## Стек

- **Бэкенд:** Python 3.12, FastAPI, SQLModel + SQLite.
- **Фронтенд:** сначала серверные шаблоны + HTMX (без сборки, быстро). Если интерфейс карточек разрастётся, поменяем на React/Vite, API при этом остаётся.
- **STT:** mlx-whisper (Mac) или faster-whisper (Windows/Linux), за интерфейсом `Transcriber`.
- **Установка:** Python-пакет, запускается одной командой (`uv`/`pipx`), на всех трёх ОС одинаково. Веб-интерфейс открывается в браузере.
- **Очередь задач:** простой фоновый воркер в процессе, без Redis.
- **Структура:**

```
app/
  api/         # маршруты FastAPI
  core/        # модели, БД, настройки
  pipeline/    # ingest, transcribe, analyze, cards
  analyzers/   # base.py (интерфейс), claude_cli.py, [claude_api.py и др. модели позже]
  transcribers/ # base.py, mlx.py, faster_whisper.py
  srs/         # расписание повторов
  web/         # шаблоны и статика
recorder/      # фаза 2: захват звука
data/          # SQLite и аудио (в .gitignore)
```

## Этапы

1. **MVP-конвейер:** загрузка аудио → транскрипт → ошибки в БД → список ошибок в вебе.
2. **Карточки и повторы:** генерация карточек из ошибок, экран повторения, SRS.
3. **Советы и статистика:** слабые места, динамика, недельная сводка.
4. **Рекордер:** автоматическая запись звонков на Mac.
5. **Зеркальный режим:** профиль собеседницы, русские карточки. Она ставит своё приложение на свой компьютер (любая ОС) и использует свою подписку Claude или другую модель через `Analyzer`. Общего сервера нет.

## Риски и допущения

- **Согласие собеседницы.** Запись разговора требует её согласия.
- **Качество ASR** на акцентной речи ниже, чем на дикторской, часть «ошибок» будет шумом. Поэтому в `error` есть пометка уверенности, и ты сможешь отклонять ложные срабатывания, а отклонённые не попадут в карточки.
- **Лимиты подписки** при очень частом использовании возможны. Именно поэтому `Analyzer` сделан заменяемым. Другие модели (в том числе локальные через Ollama) подключаются через тот же интерфейс, но разбор ошибок у них слабее.
- **Условия подписки.** Запуск `claude -p` на своём компьютере для личного использования, но точные условия стоит перепроверить на сайте Anthropic.
- **Windows и Linux** я проверить на своей стороне не смогу, у меня только Mac. Кросс-платформенный код пишем, но реальные тесты на других ОС придётся делать собеседнику.
